## Source lineage

- Merged: `HealthCheck-Dynamic-Annual-Circular-Tables-SOURCE-PATCH.zip` (includes the prior ONE-ROW customer search patch, company lookup controller and data-driven dynamic PDF tables).

## Included changes and behavior

1. Customer Search: one-line desktop toolbar (name, ID/Passport, HN, company, Booking and buttons), expandable company quick lookup, responsive on narrower displays. Existing control IDs and APIs are retained.
2. Worklist: narrow Pending Confirmation panel on left, Today's Cases on right, taller table and Search/Refresh next to each other; original EMR workflows preserved in source.
3. Corporate annual editor: section 01 parent/subsidiary data with tax ID, address, independent Payor Code and Payor Plan; multiple coordinators in one shared editor. Section 04 employee/family programs separate from editable section 09 matrix; single save action for 09; section 10 remains extra examinations.
4. Primary circular PDF: removes the fixed-position legacy first template page, generates flowing A4 tables from saved sections 00–08, then appends section 09 matrix and section 10 additional examinations; the existing server-side attachment merge remains. Existing stored PDFs are not deleted or rewritten.
5. Installer GUI: protects against an invalid log-viewer working directory and catches optional Notepad failures without collapsing the WPF window.
6. Preserves Production Only, `D:\HealthCheck\Production`, port 3000, `health_check_smart_search` database, backup/migration scripts and Update Center code.

## Critical limitations / deployment caution

- The tests for PDF creation rely on a mock `pdf-lib` object. **No real PDF generation or PDF attachment merge was tested end-to-end.** npm registry access to install real PDF dependencies failed in this environment.
- Browser screenshot tests of the final combined app could not be executed because this runtime blocked local navigation. Earlier patches had separate browser-level previews; the full merged package was checked by source tests only.
- **Windows PowerShell/WPF GUI, PostgreSQL database migrations, hospital HIS integration, Update Center upgrade, and Windows installer deployment have NOT been exercised here.** Naming the archive PRODUCTION does not certify safe deployment.
- `INSTALL-REPAIR.bat` can stop/restart the Production service. Schedule a maintenance window and back up PostgreSQL + app data before running on a live server. Existing database/data is NOT touched when producing this ZIP.
- Before deploying live, test on a separate Windows/DB environment: `http://localhost:3000/api/version`, PDF sections 00–10 and attachments, section 09 save/reload, left/right Worklist, single-row Search, and Restore/Update Center behavior.

## Installation on a test machine

1. Extract the entire archive to a new writable folder on Windows, not on top of `D:\HealthCheck\Production`.
2. Right-click `INSTALL-REPAIR.bat` → **Run as administrator**.
3. The existing installer targets `D:\HealthCheck\Production` and port `3000`. It is not an isolated test install: use a separate Windows machine/VM when evaluating this release.
4. On completion, confirm `http://localhost:3000/api/version` reports `v7.64.12` and `v7.64.12-production`, then test the features and restore path.
