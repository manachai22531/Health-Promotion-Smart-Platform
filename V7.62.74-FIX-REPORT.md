# v7.62.75 Fix Report

## 1. Package Type / Station save conflict
Root cause: the Package Save flow compared the full `primaryPackages` object. `readPrimaryPackages()` enriches rows with HIS metadata such as price/name, so an unchanged package could be detected as a customer-package change. The flow then called the patient record PATCH first, which is protected by the global app_state revision. A stale revision could return HTTP 409 before the independent Type/Station transaction was reached.

Fix:
- Detect customer primary-package change by normalized Package Code membership, not refreshed HIS metadata.
- Save `/api/package-item-settings/batch` first and independently from customer revision.
- Type + Station still save in one PostgreSQL transaction.
- Customer record PATCH runs only when package membership or accepted package extras really changed.
- Progress is dynamic instead of fixed 1/4..4/4.
- If Type/Station succeeded but a separate customer-package save later fails, UI reports the partial state explicitly instead of implying Type/Station failed.

## 2. Package HIS Name column
- Name is left aligned.
- Name receives the remaining table width.
- Company/Total price/Action columns receive fixed sensible widths.

## 3. Auto Sync -> Active/Inactive
- Added an explicit `performHisPackageSyncThenReconcile()` flow.
- Auto Sync first refreshes package data, then runs batch Active/Inactive reconciliation.
- Manual HIS package sync uses the same sequence.
- Schedule status records Active/Inactive totals and marks PARTIAL if status reconciliation fails.
