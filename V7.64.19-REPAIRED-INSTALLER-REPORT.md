# HealthCheck v7.64.19 PRODUCTION — Repaired Installer

This ZIP supersedes the earlier v7.64.19 Windows installer that failed preflight.

## Confirmed root cause
The original installer had `package.json` and `VERSION.txt` set to v7.64.19 but
`server.js` retained `const RELEASE_NAME = 'v7.64.18-production';`. The
production worker correctly rejected this mismatch **before Preflight/Backup/Deploy**.
The WPF installer GUI also emitted a secondary `ShowDialog()` exception that masked
the original error on the user's system.

## Corrections
- `server.js`: set `RELEASE_NAME` to `v7.64.19-production`.
- `package-lock.json`: synchronize root package metadata to `7.64.19`.
- `tools/production-installer-worker.ps1`: synchronize safe fallback version.
- `tools/production-installer-gui.ps1`: catch dispatcher timer callback exceptions
  to avoid crashing the whole WPF dialog after worker failure. An invalid
  Windows working directory is reset defensively before status polling.
- `PRODUCTION-README.txt`: synchronize version.
- Regenerate source SHA-256 manifests after repacking.

## Installation
1. Do **not** retry the old v7.64.19 ZIP.
2. Download **Repaired** ZIP, extract every file to a fresh local folder.
3. Back up your database and files. Run `INSTALL-REPAIR.bat` as Administrator
   during a maintenance window. The installer may stop/restart Production.
4. Verify `http://127.0.0.1:3000/api/version` reports `v7.64.19` and
   `environment=production` and check application flows.

## Verification scope
Static production version checks, file-hash manifest checks, JS syntax and
existing Node regression tests performed. **Not** a live Windows/PowerShell,
PostgreSQL, HIS, or full installer end-to-end test.
