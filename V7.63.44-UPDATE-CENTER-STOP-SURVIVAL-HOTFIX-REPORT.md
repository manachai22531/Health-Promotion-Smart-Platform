# v7.63.44 — Update Center STOP Survival Hotfix

## Root cause verified from Production log
The v7.63.42 Update Center started a detached Node helper and then ran `taskkill /PID <ProductionPID> /T /F`. On Windows `/T` terminates the target process tree, so the updater helper could be terminated together with Production immediately after STOP. The observed log stopped after `RUN stop-server` and `update-status.json` remained at `STOP`.

## Fix
- `stopServer()` now terminates only the exact Production PID: `taskkill /PID <PID> /F`.
- The updater helper is explicitly protected from self-termination (`targetPid === process.pid`).
- STOP status/log records both `serverPid` and `helperPid` and confirms that the API is offline before continuing to DEPLOY.
- Child command timeout cleanup still uses `/T /F`; this is intentionally separate from Production STOP.
- Corrected the updater semantic version comparison (`7.62.99` is no longer considered newer than `7.63.1`).

## One-time v7.63.42 bridge
A separate `HealthCheck-v7.63.42-UPDATE-CENTER-HOTFIX.zip` patches only `D:\HealthCheck\Production\tools\app-update-helper.js`. This is required once because the currently running v7.63.42 server copies its own helper before it can deploy a new package. The hotfix does not change application data or database schema.

## Upgrade path
1. Apply the one-time v7.63.42 hotfix.
2. Ensure Production is running on port 3000.
3. Upload `HealthCheck-v7.63.44-PRODUCTION-UPDATE-CENTER-STOP-FIX-INSTALLER.zip` in Update Center.
4. Run Preflight, then Install Update.
5. Expected phases: PREFLIGHT → BACKUP → STOP → DEPLOY → MIGRATE → START → HEALTH → SUCCESS.
