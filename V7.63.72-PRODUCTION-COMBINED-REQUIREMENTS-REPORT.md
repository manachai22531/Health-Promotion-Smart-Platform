# HealthCheck v7.63.72 Production Combined Requirements

## Release scope
This release continues from v7.63.71 and combines the requirements agreed before the Android-client discussion.

## Project Booking
- PackageName is constrained to one line with ellipsis so long package descriptions no longer increase booking-row height.
- Full PackageName remains available via the native title tooltip.
- Booking close button is moved into the Booking header flow and styled red instead of floating at the extreme screen edge.
- Booking Status is sourced from HIS `patientlog` using the row HN + VN.
- The latest patientlog record is selected by `insdate DESC NULLS LAST`, with `id DESC NULLS LAST` as the tie-breaker.
- The value displayed in the Status column is `tovalue`; when no matching log exists the UI displays `-`.
- Status lookup is performed as a bulk query for visible booking rows, not one database query per row.

## User and Role management
- User management is redesigned into two main columns: Role and User.
- The previous instructional step row is removed.
- The User column can synchronize users from the configured HIS directory table (`doctorTable`, default `usermas`).
- `ดึงข้อมูลจาก HIS` appears immediately before `+ เพิ่มผู้ใช้`.
- HIS fields are discovered dynamically so common username/name/department/position columns can be mapped without hardcoding one schema.
- Existing local users are matched by HIS user ID or username and updated with HIS profile data.
- New HIS users are imported disabled with no local password by design; an administrator must assign/confirm Role and set a local password before enabling login.
- Existing Role/permission management and permission audit are preserved.

## Preserved v7.63.71 capabilities
- Multi-project selection and bulk EMR retrieval.
- Wide blocking Live Progress modal during bulk EMR, preventing duplicate clicks while processing.
- Per-project and per-booking progress/status details.
- Compact project rows and inline remarks.
- Existing Booking sticky columns, action buttons, HN/VN coloring and EMR status behavior.

## Production / Update Center safeguards
- Release: `v7.63.72-production`
- `APP_ENV=production`
- `PORT=3000`
- Production database name guard remains `health_check_smart_search`.
- Update package keeps `server.js`, `package.json`, `VERSION.txt`, and `INSTALL-REPAIR.bat` at ZIP root.
