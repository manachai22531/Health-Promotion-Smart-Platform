EDITABLE HIS SQL
- Nine scoped jobs: patient name/DOB second-pass; HIS users; appointments by date; appointments by date/location; appointments by HN; LAB by HN/VN; X-ray request group; patient packages all; patient packages filtered.
- apiManage and a live password-based config unlock are required for all management/log endpoints.
- Configure existing HIS database connections first. Default SQL is built from the real schema/column mappings; no fictional connection or SQL is activated.
- Edit SQL, keep required output aliases and parameters, enter test values and test successfully before saving with a reason. Test proof is tied to actor, exact SQL and current connection/default plan, expires after 10 minutes, and saved revisions prevent overwriting concurrent edits.
- Managed SQL runs inside PostgreSQL READ ONLY transactions, extended query mode and statement/lock timeouts. Multi-statements, write/DDL commands and non-allowlisted function calls are rejected. Required column contracts and patient/date scopes are checked. Test results are capped at 100 rows and masked; runtime bounds match each managed job's limits.
- Reset restores built-in SQL without deleting history. App DB tables his_sql_configs and his_sql_audit are created additively on first SQL-manager use.
- Durable SQL audit: actor, action, revision, before/after SQL, reason, outcome, duration, row count and SQLSTATE. Parameter values, query result values and database passwords are not stored. CSV export neutralizes spreadsheet formula prefixes. Legacy HIS API logs remain in their existing gated HIS API section.
- SQL administration changes data-fetch queries only; it does not turn HIS writes into editable SQL.
