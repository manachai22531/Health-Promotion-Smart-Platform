# Personal health book / Gemini lab drafts

- Add review button in the book editor. A read-only iframe uses all seven editor sections, current unsaved clinical fields and saved group interpretations. It does not persist or approve. The separate saved PDF action uses the existing staff permission/doctor assignment/approval checks.
- Replace the sparse health-book PDF renderer with a shared visit-scoped model and A4 HTML renderer. Parse nested body/data/Patient/array/JSON HIS envelopes; show every test, unit, reference and group/category note plus saved history, physical exam, ICD and advice. Missing or pending tests remain pending, never invented as normal. PDF sections flow across as many A4 pages as needed.
- Prefix the disk cache with book-v86 to prevent reuse of older sparse PDFs. Non-health customer PDFs and customer package QR remain unchanged.
- Add Gemini setup in System & API for apiManage users. Configure your own enabled Gemini model and API Key; no default model/key is fabricated. Secret settings are stored server-side in data/gemini-lab-settings.json with restrictive file mode where supported, never included in installer payloads or returned by the API. GEMINI_API_KEY and GEMINI_MODEL environment variables are optional initial values.
- Staff with emrView/emrEdit can preview a saved single-VN lab payload before explicitly sending. Only age, sex and allowlisted lab fields are sent; identity columns are omitted and known identifier strings are redacted. The doctor should review the payload before sending free text externally.
- Gemini uses the fixed Google endpoint and server key header with a 45-second timeout, concurrency bounds, schema/size checks, source-version checks and audit metadata. No clinical data or API keys are written to generation audit details. Provider failures do not alter records.
- Results are editable drafts. Editing invalidates the review checkbox. Applying revalidates source data and fills the existing draft inputs; existing notes/advice are preserved. Save through the normal draft/group-interpretation controls. There is no automatic record save, diagnosis, prescribing or approval.
- Existing Template-based automatic interpretation remains available. No QR expiry/signing changes or database schema migration.

Validation: 89 release tests (80 existing + 9 new); actual PostgreSQL/Chromium report generation with nested Patient data, 25 CBC rows plus other groups, saved notes/history/exam/ICD/advice, strict VN isolation, draft print gate, editor unsaved preview, Gemini explicit-send/review checkbox/edit invalidation/no-auto-write and normal draft persistence. Provider calls are mocked; no live Google account/API Key or real patient data is used. Physical Windows GUI/UAC/VBS/Task Scheduler/phone/printer testing remains outside this Linux environment.
