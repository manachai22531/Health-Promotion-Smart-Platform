HealthCheck v7.64.71 — Windows Production Installer

รวมการแก้ไขทั้งหมด v7.64.68–70 พร้อม Worklist ตารางเดียวตามม็อกอัป
- รวมรอยืนยัน รอเปิด Visit รอสั่ง Order ส่งตรวจแล้ว และเสร็จสิ้น
- กรองสถานะจากแถบเดียว แถวอยู่ในตารางเดิมเมื่อเปลี่ยนขั้นตอน
- รอยืนยันแสดงจาก Booking ที่นัดในวันที่เลือก ไม่สร้าง Visit/ยืนยันให้อัตโนมัติ
- ปุ่มยืนยัน/เปิด Visit/สั่ง Order เปิดรายละเอียดให้ตรวจสอบก่อนดำเนินการ
- งานแบบกลุ่มใช้ได้เฉพาะส่ง Order สำเร็จ มี HN และ VN
- คงตัวกรองบริษัท/โครงการ/วันที่/ค้นหา และ EMR/Charge Close เดิม

สำหรับเครื่องในภาพที่ยังใช้ v7.64.68: แนะนำติดตั้งโดยตรงครั้งนี้
1. รอให้ตัวอัปเดตหรือตัวติดตั้งเดิมสิ้นสุด ห้ามเปิดซ้อนกัน
2. แตก ZIP ทั้งหมดลงโฟลเดอร์ใหม่
3. เปิด INSTALL-REPAIR.vbs แล้วอนุญาต UAC
4. รอ Complete SUCCESS และตรวจเวอร์ชัน v7.64.71 จากนั้น Ctrl+F5

หากต้องการใช้ Update Center บน v7.64.68
1. แตก ZIP นี้ แล้วเปิด REPAIR-UPDATE-CENTER.vbs หนึ่งครั้ง
   ตัวซ่อมตรวจ hash และสำรอง helper เดิม ไม่หยุดแอป/ไม่แก้ฐานข้อมูล
2. Upload ZIP ตัวติดตั้งนี้ใหม่ แล้ว Preflight/Install ตามลำดับ
   ตัวซ่อมปฏิเสธหากมีงานอัปเดตที่ยังทำงานอยู่
สาเหตุ: preflight เก่าทำงานก่อน deploy ZIP ใหม่ จึงต้องซ่อม helper เก่าก่อน
ตัวช่วยใหม่ตรวจ public /api/health + /api/version และยังตรวจ Production/DB/version

การสำรอง Source และฐานข้อมูลยังเป็นขั้นตอนบังคับ อาจใช้เวลานานตามขนาด
Live log/heartbeat แสดงสถานะงาน ระยะเวลาบีบอัด Source ไม่ได้ถูกเร่งในรุ่นนี้

รายละเอียดการแก้ไขที่รวมมาจากรุ่นก่อน

HealthCheck v7.64.71 — Windows Production Installer / Update Center Package

แก้ปัญหา Production health/version preflight failed
- Update Center ตรวจ /api/health + /api/version ที่ไม่ต้องใช้ staff session
- ตรวจ Production lock, เวอร์ชัน/Release และ PostgreSQL จริง ทั้งก่อนและหลังอัปเดต
- แสดง HTTP status/endpoint เมื่อ probe ผิดพลาด โดยคงการสำรองและ rollback เดิม
- หากเครื่องยังใช้ตัวช่วยเก่า ต้องใช้ไฟล์ซ่อม Update Center หนึ่งครั้งก่อน
  หรือใช้ตัวติดตั้ง Windows ตามขั้นตอนด้านล่างเพื่อข้าม Update Center เดิม

รวมการแก้ไขล่าสุดหลัง v7.64.69
- ช่องแพ็กเกจคู่สัญญาที่เลือกขยายเต็มพื้นที่ที่เหลือและยืดตามเนื้อหา
- บริษัทในเครือค้นหา Payor Code/Plan จาก Master แยกกันแต่ละบริษัท
  เปลี่ยน Payor แล้วล้าง Plan เดิม แสดงชื่อคู่รหัส บันทึกเฉพาะรหัส
- แท็บประวัติการเข้าสู่ระบบในศูนย์ปฏิบัติการ ใช้สิทธิ์ Audit Log
  ค้นหา กรองวันที่/ผล และแบ่งหน้า แสดงเวลาไทย ผู้ใช้ ชื่อ Role IP และผล
  แยกสำเร็จ/ผิดพลาด/ต้องเปลี่ยนรหัสผ่าน/ระงับชั่วคราว
  ไม่เก็บ password/hash/token ในข้อมูลประวัติใหม่
  ข้อมูลเก่าอาจไม่ระบุผู้ใช้หรือผล ไม่อนุมานว่าสำเร็จจาก HTTP 200 เก่า

รวมการแก้ไข v7.64.68–69 ทั้งหมด
- ปุ่มบันทึก 02–04 บริษัทใหม่พร้อมปี สลับหน้ากรอก 00/01 โดยลำดับ PDF คงเดิม
- แผงตั้งค่า ประกายดาว Password Expired และ Idle Logout 15 นาทีปรับตาม role
- ตรวจแบบไม่ฟังผล ไม่มีคูปองอาหาร รูปแบบบริการอื่นแทน Walk in
- ยกเลิกตารางโปรแกรม ดาวน์โหลดเทมเพลต/นำเข้า Excel และแนบ PDF ตารางโปรแกรม
- ซ่อนแถบ HIS จนกว่าจะยืนยันการตรวจ และตัวติดตั้งหน้าต่างเดียวพร้อม live log

ติดตั้ง Windows โดยตรง
1. รอให้ตัวติดตั้ง/ตัวอัปเดตเดิมหยุดทำงานก่อน ห้ามเปิดซ้อนกัน
2. แตก ZIP ทั้งหมดในโฟลเดอร์ใหม่ ไม่ใช่โฟลเดอร์ Production ที่รันอยู่
3. เปิด INSTALL-REPAIR.vbs และอนุญาต UAC
4. รอ Complete SUCCESS จากนั้นตรวจ /api/version เป็น v7.64.71 แล้วกด Ctrl+F5
เป้าหมาย D:\HealthCheck\Production / พอร์ต 3000 / health_check_smart_search
ตัวติดตั้งสำรอง Source/ฐานข้อมูลและรักษา .env/ค่าระบบเดิม
การบีบอัด Source backup ยังใช้วิธีเดิมและอาจใช้เวลานาน

อัปเดตผ่าน Update Center
1. หากเจอ health/version preflight failed จากรุ่นเก่า ให้รัน REPAIR-UPDATE-CENTER.vbs
   ในไฟล์ซ่อมแยกหนึ่งครั้ง (ไม่ต้องใช้ไฟล์ซ่อมเมื่อติดตั้ง Windows โดยตรง)
2. อัปโหลด ZIP ตัวติดตั้ง v7.64.71 นี้ใหม่ แล้วกดตรวจความพร้อมก่อนติดตั้ง
3. การตรวจความพร้อมต้องผ่านก่อนกดติดตั้งจริง
4. รอ SUCCESS และตรวจเวอร์ชันจริง v7.64.71 จากนั้น Ctrl+F5

ยังไม่ได้รันตัวติดตั้ง/ซ่อม GUI, UAC, Robocopy หรือ Windows Update ครบวงจรบน Windows จริง
