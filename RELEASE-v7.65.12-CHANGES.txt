HealthCheck v7.65.12 — 2026-11-04
Includes v7.65.11 and all approved pending work:
1. Search fields: ID/Passport, HN, Name, Company, Booking. Original search theme remains.
2. Bulk company/year deletion: Select All and Clear Selection apply to visible filtered rows. Hidden selections remain counted. Preview/backup/reason/confirmation and server safeguards are retained; selecting does not delete.
3. New UI theme is scoped to DataCenter shell and its internal modules. Other staff/customer pages keep the original theme.
4. Customer detail: Summary / Navigation tabs in existing right pane. Seven editable stations based on FM-CHU-004 Rev.01: Register; Assessment/history; Lab; X-ray; Cardio; Doctor/report delivery; Discharge/Consult. Saved customer identity fills the header. Clinical values remain blank until staff enter them. Save is per customer membership/company year, revision checked and audited. Closed/retrospective policy and permissions are enforced. Refresh/PDF/print use the selected document. PDF uses the same renderer and embedded Thai fonts.
5. Order & Station: Navigation Mapping tab. Rules match specified type, station, specimen and/or exact item code. Per-item override has priority, including explicit no-selection. Multiple matching orders deduplicate into one checkmark. A local trial tool previews a sample match. No default LAB=Blood guess; administrators configure rules. No settings are seeded from fictional examples.
6. Automatic navigation marks derive from saved selected primary/additional packages expanded into actual order items, using current item type/station/specimen settings. Unselected entitlements are excluded. Missing catalog/mappings are reported. Manual edits are stored separately; automatic marks clear when matching orders disappear. Reset-to-auto removes manual overrides. Checkmarks indicate planned tests, never completion or results, and send no HIS orders.
7. DataCenter VN/OpenVisit: date-range batches from interfacemobilecheckup_patientopenvisit.insdate, inclusive final date in Asia/Bangkok, up to 366 days per request. 100-row pagination with exact total and newest insertion first. VN is parsed from the response, never substituted with a request VN. Malformed/ambiguous responses and HN/VN mismatch are marked. Historical Local/OpenVisit outcomes and latest opdvisit state are separate. Each displayed page is checked read-only against the same configured HIS connection; changing page checks that page. No writes to hospital tables and no automatic resend. Raw unknown HIS status codes are retained rather than guessed.
8. Schema 0220: idempotent customer_navigation_sheets migration with membership FK/cascade. Existing 0219 HIS history repair and PDF module preflight retained.
Installation: back up database, extract the entire archive and run INSTALL-REPAIR.bat as Administrator. Wait for health check and hard refresh to verify v7.65.12. Copying source alone does not install locked dependencies or run installer migrations. Navigation editing requires receiveCreate, printing summaryPrint; mapping administration orderItemManage. VN/OpenVisit requires dataCenterView and customerSensitiveView and uses Patient Package/Radiology DB settings from System & API.
Pruksa upload: put the supplied PowerShell script, ZIP and checksum in one folder and run the script locally. It uses local Git authentication and verifies a fresh remote download. No credential is embedded.
Not part of this release: the cancelled personal/package layout redesign. Existing UNKNOWN HIS operations still require reconciliation; they are never blindly resent.
