# HealthCheck v7.63.80 — Mapped HIS User Sync Filter

## Base
- Built from v7.63.79 Production.
- Production only (`APP_ENV=production`, `PORT=3000`).
- Update Center root layout preserved.

## Change requested
`Mapping Role` is now authoritative for HIS User Sync.

### Sync behavior
- Only mappings that are **enabled** and have a valid **HealthCheck Role** are eligible.
- The selected `lovcptypid` values are applied in the HIS SQL `WHERE` clause **before `LIMIT 5000`**.
- Disabled mappings, unmapped types, and mappings without a role are not imported.
- Existing v7.63.79 idempotent username upsert/deduplication is preserved.
- Existing LOCAL users keep their local password, active state, and manually assigned role.

### Mapping Role UI
- User counts are calculated by `lovcptypid` without the 5,000-row list limit.
- The Mapping dialog shows a live summary: enabled mapped types, users that will sync, eligible users, and users excluded by mapping.
- Rows that are enabled but have no role are reported as pending and are excluded from Sync.

### Sync result summary
The completion message reports:
- created
- updated
- skipped during sync
- excluded because mapping is not enabled/selected
- inactive HIS users
- expired HIS users
- duplicate HIS rows / repaired duplicate app users / conflicts
