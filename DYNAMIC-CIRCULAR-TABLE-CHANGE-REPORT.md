# HealthCheckup Smart Search — Dynamic Circular Table Source Patch

## Requirement
Remove the static first page of the hospital's corporate-circular PDF template. Generate a flowing A4 document directly from the saved company/year sections, keeping their natural order instead of drawing text over fixed PDF coordinates.

## Implementation

- `corporate-circular-pdf.js`: no longer copies the first page of `templates/corporate-circular-template.pdf`. Instead builds a fresh PDF document from saved data, then appends 09, 10.
- `corporate-circular-sections.js` (new): renders 00–08 as a flowing, paginated table with repeated page header and section headers; grows rows based on Thai/English text wrapping rather than cutting overflowing content.
- Section 01 includes parent and up to 20 subsidiaries, with `1.1`, `1.2` etc. Each company retains its own tax number, address, employee count, Payor Code/Plan and company code. Coordinator is printed once.
- Section 04 retains employee/family programs and conditions. Section 09 keeps the program-checkup comparison matrix; Section 10 keeps extra billing/cash packages.
- `company-program-matrix.js`: matrix page title now clearly identifies heading 09.
- `app.html`: right-hand PDF preview note reflects the new table-driven output. The latest one-row customer search layout and `assets/customer-search-one-row.js` were carried forward rather than reverting the prior UI patch.
- The server's same `buildCorporateCircularPdf` entry point is used for preview, circular download and primary PDF creation. Its existing attachment-merge step remains unchanged.

## Test results

`node --test release-candidate-v76410-subsidiary-directory.test.js release-candidate-v76411-production-package.test.js release-candidate-v76410-worklist-matrix-fix.test.js release-candidate-dynamic-circular-table.test.js`

20/20 tests passed using mocked pdf-lib. Tests cover all 00–08 headings, parent and child companies, 20 child companies spanning pages, long narrative text, 09→10 ordering, and preserved backend attachment merge.

Node JavaScript syntax checks passed for all edited JS modules.

**Limitations:** The test environment does not have the `pdf-lib`/`@pdf-lib/fontkit` runtime dependencies available locally, and registry access failed, so a real PDF produced by the Node renderer could not be tested. The separate preview PNGs are renderings of mocked drawing operations for layout review only, not PDFs generated by the live server. PostgreSQL, deployment on Windows and PDF merging were not tested end-to-end. Do not deploy to live Production before those tests.

## Compatibility

- Source base: v7.64.11 Production installer + last one-row search source patch.
- Original static PDF template remains in the project for compatibility, but is not read by the new corporate circular code.
- No existing database records or saved PDF history are deleted. Historical PDFs will remain unchanged; only newly generated PDFs will use the new layout.
- No installer/release was generated. Build a new Production installer only upon explicit request.
