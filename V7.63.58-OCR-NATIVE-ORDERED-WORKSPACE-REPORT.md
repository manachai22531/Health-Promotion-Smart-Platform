# HealthCheck v7.63.58 — OCR Native Ordered Workspace

## Scope
This release fixes the OCR workspace issues reported after v7.63.57. The A4 summary footer is intentionally left unchanged because the user confirmed it is already fixed.

## OCR integration
- Removed the OCR iframe from `app.html`.
- Added a native OCR host (`#ocrNativeHost`) inside the existing `ocrView` application view.
- Added `assets/ocr-native.js`, which renders the OCR workspace directly inside the application using a Shadow DOM component. This keeps OCR CSS/IDs isolated without opening another HTML page or iframe.
- OCR API calls, scanner flow, batch queue, setup/export, human review, notes and audit continue to use the existing same-origin Production APIs.
- Legacy `/ocr` and `/ocr-review-mockup.html` URLs now redirect back to the main application as `/?view=ocr`.

## Session handling
- Opening OCR now validates `/api/auth/session` first.
- If the server-side session expired after a restart/update, the main application login screen is shown.
- A login page can no longer be rendered inside the OCR workspace.
- `?view=ocr` is supported after login for legacy/deep-link redirects.

## OCR layout cleanup
- OCR controls are grouped into one compact control bar.
- Progress steps use a compact fixed row.
- Batch import actions are together: `+ เพิ่มเอกสาร`, `OCR ที่เลือก`, `OCR ทั้งหมด`, `ล้างรายการ`.
- Search/filter/selection are separated into one compact command row.
- Main work area is a stable three-column layout: approximately 22% Document Queue / 36% Preview / 42% OCR & Human Review.
- Each panel scrolls internally; the main page does not require horizontal scrolling at normal desktop widths.
- OCR document action/status/error navigation is consolidated in the Human Review toolbar.
- Existing OCR command de-duplication from v7.63.57 is preserved.

## A4 summary
- No A4 layout/action changes were made in this release.
- Existing single-row footer behavior from the previous release is preserved.
