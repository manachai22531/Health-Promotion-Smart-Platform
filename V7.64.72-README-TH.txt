HealthCheck v7.64.72 — Windows Production Installer

แก้การติดตั้งล้มเหลวจากพื้นที่ดิสก์ไม่พอตาม log วันที่ 22 ต.ค. 2026
สาเหตุเดิม: Compress-Archive สำรอง Source ล้มเหลวก่อน deploy/migration

การแก้ไข
- สำรอง Source เป็น ZIP โดยอ่านไฟล์ต้นทางลง ZIP โดยตรง ไม่คัดลอก Source
  ทั้งชุดไปโฟลเดอร์ temp ก่อน จึงลดพื้นที่เพิ่มระหว่างสำรอง
- ตรวจขนาด Source และพื้นที่ว่างก่อนหยุดแอปเดิม หากไม่พอแสดง available/required
- คิดพื้นที่อย่างระมัดระวัง: ขนาด Source เผื่อ ZIP overhead + payload + 1 GiB
  เป็นขั้นต่ำสำหรับงานติดตั้ง ไม่ใช่การรับประกันพื้นที่สำหรับ DB ขนาดใหญ่
- ตรวจพื้นที่ซ้ำหลังหยุดแอปและสแกน snapshot สุดท้าย
- เก็บ .env, hidden configuration, Source และ data/uploads ทั้งหมด
- ไม่รวม node_modules/logs/backups/tmp/updates/.git ที่ระดับราก
  (ไม่ข้ามโฟลเดอร์ชื่อเดียวกันภายใน data ของผู้ใช้)
- แสดงความคืบหน้าทุก 10 วินาทีขณะเขียน ZIP; ตรวจรายการและขนาดไฟล์
  ก่อนเผยแพร่ ZIP สำเร็จ ลบเฉพาะ partial ZIP ที่ตัวเองสร้างเมื่อเขียนล้มเหลว
- ไม่เขียนทับ backup เก่า ไม่ลบข้อมูลจริง/backup เก่าอัตโนมัติ
- ถ้าสำรองล้มเหลวหลังหยุดแอป พยายามเปิดแอปเดิมและแสดงข้อผิดพลาดของ launcher
- การสำรองฐานข้อมูลยังเป็นขั้นตอนบังคับเดิม

การใช้หลังเหตุการณ์พื้นที่เต็ม
1. ปิดตัวติดตั้งเดิมที่ขึ้น FAILED
2. ตรวจพื้นที่ไดรฟ์ D: และย้าย backup ZIP เก่าที่ต้องเก็บไปไดรฟ์อื่น
   ห้ามลบ Production/data, .env หรือฐานข้อมูล PostgreSQL
   ตัวติดตั้งใหม่จะบอกพื้นที่ขั้นต่ำที่ต้องใช้ก่อนหยุดแอป
3. แตก ZIP ใหม่ทั้งชุดลงโฟลเดอร์ใหม่ แล้วเปิด INSTALL-REPAIR.vbs / อนุญาต UAC
4. รอ Complete SUCCESS ตรวจเวอร์ชัน v7.64.72 แล้ว Ctrl+F5

เครื่องยังอยู่ v7.64.68 แนะนำติดตั้งโดยตรงตามข้อ 3
หากใช้ Update Center ต้องเปิด REPAIR-UPDATE-CENTER.vbs จาก ZIP ที่แตกแล้ว
ก่อน Upload ZIP ใหม่ เพื่อซ่อม preflight helper เก่าเพียงครั้งเดียว
ห้ามเปิดตัวติดตั้ง/ตัวอัปเดตพร้อมกัน
