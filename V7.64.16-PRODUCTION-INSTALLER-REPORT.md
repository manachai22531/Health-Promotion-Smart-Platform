# HealthCheck v7.64.16 PRODUCTION — Single confirmation workflow

## Changes
- Initial "ยืนยันการตรวจ" saves selected main packages, billed/self-paid extras, contract packages, checkupConfirmedAt and visitedAt via a single PATCH request before presenting A4.
- The footer no longer has the redundant "ยืนยันและบันทึกการตรวจ" button. "บันทึกการแก้ไขรายการตรวจ" appears only if a previously confirmed record has changed selections and the user has receiveEdit permission, before a successful HIS Order.
- receiveCreate controls first confirmation; receiveEdit controls revisions; receiveFinalize remains required for HIS Order (not automatic).
- Existing HIS /api/his/order still requires persisted visitedAt, HN and VisitUID/VN, and remains guarded against duplicate orders. Worklist continues to require successful OrderHIS before moving to Today's Cases.
- Preserve v7.64.15 fixes (PDF fastpath, single-row search, section 09, Update Center).

## Important caveats
- Uses the existing patient PATCH and then the existing checkup audit endpoint: these two requests are not one DB transaction. If the audit request fails, the confirmation still succeeds, with a visible warning; operational reconciliation should be considered.
- If a network failure occurs during save, refresh record state before trying again; the server may have saved it.
- The legacy visitedAt field is retained for compatibility with HIS and customer-edit locks.
- No live Windows, PostgreSQL, HIS, or PDF end-to-end test has been completed in this environment. Do not equate structural tests with production certification.
- Review package totals, pending Worklist stage, and permissions in a staging/test environment before production rollout.

## Deployment
- Production Only, Port 3000, destination D:\HealthCheck\Production. Backup first and schedule a maintenance window. The installer may restart the running service.
- Windows installer entry point: INSTALL-REPAIR.bat (Run as administrator).
