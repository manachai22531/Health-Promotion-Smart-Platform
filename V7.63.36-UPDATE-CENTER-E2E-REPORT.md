# v7.63.36 — Production Update Center End-to-End Report

## Scope

Validated and hardened the complete Production Update Center path:

`Precheck → Backup → Stop → Deploy → Migrate → Start → Health → Rollback`

## Root cause fixed

`migrations/0190_production_only_cleanup.up.sql` in v7.63.35 began with a standalone backslash. `psql` treated it as an invalid meta-command and terminated with exit code 3 while `ON_ERROR_STOP=1` was enabled.

## Migration safety

- Removed the invalid backslash.
- Wrapped the migration in `BEGIN` / `COMMIT`.
- Made OCR audit table and index creation idempotent.
- Guarded the HIS connection cleanup by checking the table and required columns.
- Kept the schema migration marker retryable with `ON CONFLICT`.
- Preflight rejects migration files containing psql meta-commands or lacking a transaction.
- A corrected migration is detected by content even if a failed v7.63.35 deployment already copied a file with the same name.

## Update Center safety

- Production remains running until package extraction, environment checks, PostgreSQL tools, database connectivity, disk/write access, current version and health checks pass.
- Source and custom-format PostgreSQL backups complete before Production is stopped.
- Backup output is verified to exist and be non-empty.
- Archive extraction, source copy, database dump/restore, psql, npm, stop, start and health checks all have finite timeouts.
- Timed-out Windows commands terminate the entire process tree.
- Dependency comparison ignores release-number-only changes, so `npm ci` is skipped when dependencies are unchanged.
- A migration/start/health failure restores both source and database, then verifies that the previous version starts again.

## Regression coverage

`release-candidate-v76336-update-center-e2e.test.js` covers the 0190 defect, idempotency guards, phase order, hard timeouts, content-based migration retry, database rollback and dependency-skip behavior.

## Result

The v7.63.36 package is designed for installation directly through Production Update Center. Operators do not need to stop Production manually. A live server dry run remains recommended before pressing Install Update because local validation cannot reproduce the server's PostgreSQL credentials, permissions, disk and active process state.
