# HealthCheck v7.63.59 — OCR Menu / Native Runtime Fix

## Issue reproduced from v7.63.58
The OCR icon was visible and the hover tooltip worked, but clicking it could appear to do nothing.

Two defects were found in the v7.63.58 integration:

1. The OCR menu waited for `/api/auth/session` before changing the application view. A delayed session check made the menu look unresponsive.
2. `assets/ocr-native.js` contained the OCR markup and styles, but the generated native runtime wrapper was empty. This meant the standalone OCR behavior (Batch Upload, OCR buttons, Scanner, Setup, Review, etc.) was not actually initialized in the native app view.

## Fixes in v7.63.59
- OCR menu opens the native `ocrView` immediately, then verifies the server session in parallel.
- The top navigation capture handler has an explicit OCR branch so nested icon/popover clicks cannot be swallowed.
- The normal `[data-view]` click binding also has the same explicit OCR branch as a fallback.
- Rebuilt `assets/ocr-native.js` from the Production OCR page with the full OCR JavaScript runtime included.
- OCR remains a true application view using Shadow DOM; no iframe and no standalone `.html` navigation is used.
- The native OCR runtime includes Batch Upload, OCR current/selected/all, Camera, Scanner, Scan Agent, Setup/Export, Read Zones, Human Review, Notes and Audit behavior.
- Preserved the 22% / 36% / 42% Queue / Preview / Human Review desktop workspace proportion from v7.63.58.
- Session-expiry behavior remains in the main application login layer; OCR APIs remain protected server-side.
- A4 summary footer was intentionally not changed.
