# HealthCheck v7.64.24 PRODUCTION — Elevated installer working-directory hotfix

## Root cause
The elevated PowerShell process inherited an invalid short user-profile working directory. `Set-Location` changed the PowerShell provider location, but WPF still used .NET `Environment.CurrentDirectory`, causing `ShowDialog()` to fail before displaying the installer.

## Fix
- Start the elevated launcher from verified `%SystemRoot%\Temp`.
- Set both PowerShell location and .NET process current directory to that verified location.
- Store installer runtime logs/status under Windows Temp rather than the inherited profile TEMP alias.
- Retain the v7.64.23 updater status-file lock fix and v7.64.22 Global Golden Sparkle.

## Validation
- JavaScript and PowerShell syntax checks.
- Targeted release regression covers version synchronization, WPF working-directory normalization, updater lock handling, and Sparkle behavior.
- Embedded SHA-256 manifests and final ZIP are verified during packaging.
